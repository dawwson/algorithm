### Intuition

---

- 매일 발표할 점수는 지금까지 나온 점수 중 상위 `k`개에 포함되는 점수의 최솟값이다.
- 매번 지금까지의 모든 점수를 정렬하면 필요하지 않은 하위 점수까지 반복해서 관리하게 된다.
- 상위 `k`개의 점수만 유지하면 명예의 전당의 최하위 점수만으로 발표 점수를 결정할 수 있다.
- Java의 `PriorityQueue`는 기본적으로 최솟값이 맨 앞에 위치하는 최소 힙이므로, 상위 `k`개 중 최솟값을 `peek()`로 바로 확인할 수 있다.
- 새 점수를 넣은 뒤 힙의 크기가 `k`를 초과하면 최솟값을 제거한다. 제거 후에는 더 큰 점수 `k`개만 남는다.

<br>

### Approach

---

- 매일의 발표 점수를 저장할 `answer` 배열을 `score`와 같은 길이로 생성한다.
- 명예의 전당에 포함되는 점수를 관리할 최소 힙 `pq`를 생성한다.
- `score`를 날짜 순서대로 순회한다.
  - 현재 점수를 `pq`에 추가한다.
  - 힙의 크기가 `k`보다 크면 `poll()`로 가장 작은 점수를 제거한다.
  - `peek()`로 현재 힙의 최솟값을 구해 `min`에 저장한다.
  - `min`을 현재 날짜에 해당하는 `answer[i]`에 저장한다.
- 모든 날짜를 처리한 뒤 `answer`를 반환한다.

<br>

### Complexity

---

- Time complexity: `O(n log k)`
  - `n`은 `score`의 길이이다.
  - 각 점수를 힙에 추가하는 데 `O(log k)`가 걸리고, 크기가 `k`를 넘으면 최솟값 제거에도 `O(log k)`가 걸린다.
    - PriorityQueue는 내부적으로 힙 구조(완전 이진 트리)를 사용하고 있다.
    - 새로운 점수는 힙의 마지막 위치에 들어간 후 부모와 비교하면서 최소/최대 힙 조건을 만족할 때까지 위로 이동한다.
    - 완전 이진 트리는 원소가 k개일 때 높이가 `log k`이므로 힙 요소 추가/삭제의 시간복잡도는 `O(log k)`가 된다.
    - 이를 `n`번 반복하므로 최종적으로 `(n log k)`이다.
  - `peek()`는 `O(1)`이다.

- Space complexity: `O(k)`
  - 최소 힙에는 최대 `k`개의 점수만 유지된다.
  - 반환값인 길이 `n`의 `answer` 배열까지 포함하면 전체 추가 공간은 `O(n + k)`이다.

<br>

### Code (Java)

---

```java
import java.util.PriorityQueue;

class Solution {
    public int[] solution(int k, int[] score) {

        int[] answer = new int[score.length];
        PriorityQueue<Integer> pq = new PriorityQueue<>(); // 상위 3개만 남김

        for (int i = 0; i < score.length; i++) {
            pq.offer(score[i]);
            int min;

            if (pq.size() > k) {
                pq.poll();
                min = pq.peek();
            } else {
                min = pq.peek();
            }
            answer[i] = min;
        }

        return answer;
    }
}
```
