### Intuition

---

- 지원할 수 있는 부서 수를 최대화하려면 같은 예산으로 가능한 한 요청 금액이 작은 부서부터 지원해야 한다.
- 어떤 순서로 부서를 선택하더라도, 선택된 부서 중 요청액이 더 큰 부서를 선택되지 않은 더 작은 부서로 바꾸면 지원 부서 수는 줄지 않고 사용 예산만 줄어든다.
- 따라서 요청 금액을 오름차순으로 정렬한 뒤, 예산이 허용하는 동안 앞에서부터 순서대로 지원하는 그리디 방식을 사용한다.

<br>

### Approach

---

- `d`를 오름차순으로 정렬한다.
- 정렬된 요청 금액을 앞에서부터 하나씩 확인한다.
  - 남은 예산에서 현재 요청 금액을 차감한다.
  - 예산이 0 이상이면 지원한 부서 수를 1 증가시킨다.
  - 예산이 음수가 되면 현재 부서는 지원할 수 없으므로 반복을 종료한다.
- 최종적으로 지원한 부서 수를 반환한다.

<br>

### Complexity

---

- Time complexity: `O(n log n)`
  - `n`은 부서의 수이다.
  - 요청 금액 정렬에 `O(n log n)`, 배열 순회에 `O(n)`이 필요하다.

- Space complexity: `O(log n)`
  - Java의 `Arrays.sort(int[])`가 정렬 과정에서 사용하는 호출 스택을 기준으로 한다.
  - 입력 배열을 직접 정렬하며, 그 외에는 상수 개의 변수만 사용한다.

<br>

### Code (Java)

---

```java
import java.util.Arrays;

class Solution {
    public int solution(int[] d, int budget) {
        int answer = 0;

        Arrays.sort(d);

        for (int amount : d) {
            budget -= amount;

            if (budget >= 0) {
                answer += 1;
            } else {
                break;
            }
        }

        return answer;
    }
}
```

<br>

### Code (Python)

---

```python
def solution(d, budget):
    answer = 0

    # 오름차순 정렬 후 적은 예산부터 제외시키면 부서를 최대로 나눠줄 수 있음
    for amount in sorted(d):
        if budget - amount >= 0:
            budget -= amount
            answer += 1
    return answer
```

- `sorted(d)`로 요청 금액을 오름차순 정렬한 새 리스트를 만든다.
- 작은 금액부터 예산에서 차감하며, 지원 가능한 부서 수를 세어 반환한다.
- 시간 복잡도는 `O(n log n)`, 정렬된 리스트를 위한 추가 공간은 `O(n)`이다.
