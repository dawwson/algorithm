### Intuition

---

- 목적지 `n`까지 이동할 때 사용하는 건전지의 최솟값을 구하는 문제이다.
  - `K`칸 점프하면 건전지를 `K`만큼 사용한다.
  - 현재까지 이동한 거리의 두 배로 순간 이동하면 건전지를 사용하지 않는다.
- 건전지를 아끼려면 무료인 순간 이동을 최대한 사용하고, 순간 이동만으로 갈 수 없을 때 필요한 만큼만 점프해야 한다. 따라서 매 순간 비용이 들지 않는 선택을 우선하는 **그리디 알고리즘**을 사용한다.
- 출발점 `0`에서 앞으로 이동하면 점프할 거리와 순간 이동 시점을 여러 가지로 선택할 수 있다. 반대로 목적지 `n`에서 `0`으로 돌아가면 선택이 하나로 정해진다.
  - `n`이 짝수이면 어떤 거리의 두 배로 도착한 것이므로 `2`로 나눈다. 이는 건전지가 들지 않는 순간 이동을 되돌리는 과정이다.
  - `n`이 홀수이면 어떤 정수를 두 배로 해도 도착할 수 없다. 따라서 반드시 한 칸 점프한 것으로 보고 `1`을 뺀 뒤 건전지 사용량을 `1` 늘린다.
- 예를 들어 `n = 6`이면 다음과 같이 역으로 이동한다.
  - `6 → 3`: 짝수이므로 순간 이동을 되돌린다.
  - `3 → 2`: 홀수이므로 한 칸 점프를 되돌리고 건전지를 `1` 사용한다.
  - `2 → 1`: 짝수이므로 순간 이동을 되돌린다.
  - `1 → 0`: 홀수이므로 한 칸 점프를 되돌리고 건전지를 `1` 사용한다.
  - 따라서 필요한 최소 건전지 사용량은 `2`이다.
- 이 과정은 **이진수**로도 설명할 수 있다.
  - `2`로 나누는 것은 이진수를 오른쪽으로 한 칸 이동하는 것과 같다.
  - 홀수에서 `1`을 빼는 것은 이진수의 마지막 `1`을 없애는 것과 같다.
  - 따라서 최소 건전지 사용량은 `n`의 이진 표현에 포함된 `1`의 개수와 같다. 예를 들어 `6 = 110₂`이므로 `1`이 두 개이고 답은 `2`이다.

<br>

### Approach

---

- 건전지 사용량을 저장할 `battery`를 `0`으로 초기화한다. 최적의 이동에서는 한 칸 점프만 사용하므로 이 값은 점프 횟수와도 같다.
- 목적지 `n`에서 출발점 `0`으로 역으로 이동한다.
- `n`이 `0`이 될 때까지 반복한다.
  - `n`이 짝수이면 순간 이동으로 도착한 경우이므로 `n`을 `2`로 나눈다. 건전지는 사용하지 않는다.
  - `n`이 홀수이면 한 칸 점프가 반드시 필요하므로 `n`에서 `1`을 빼고 `battery`를 `1` 증가시킨다.
- `n`이 `0`이 되면 누적한 최소 건전지 사용량 `battery`를 반환한다.

<br>

### Complexity

---

- Time complexity: `O(log n)`
  - `n`은 처음 주어진 목적지 거리이다.
  - 짝수이면 `n`을 바로 절반으로 줄이고, 홀수이면 `1`을 뺀 다음 반복에서 절반으로 줄인다.
  - 최대 두 번의 반복마다 값이 절반 이하가 되므로 전체 반복 횟수는 `O(log n)`이다.

- Space complexity: `O(1)`
  - 목적지 값과 건전지 사용량만 갱신하며 입력 크기에 비례하는 자료구조를 사용하지 않는다.

<br>

### Code (Java)

---

#### 그리디

```java
import java.util.*;

public class Solution {
    public int solution(int n) {

        int battery = 0;

        while (n != 0) {
            if (n % 2 == 0) {
                n /= 2;
            } else {
                n -= 1;
                battery += 1;
            }
        }

        return battery;
    }
}
```

<br>

#### 비트 조작

```java
public class Solution {
    public int solution(int n) {
        return Integer.bitCount(n);
    }
}
```

- 목적지 `n`의 이진 표현에서 `1`인 비트의 개수를 바로 반환한다.
- 기존 코드는 홀수일 때 `1`을 빼는 과정을 반복하며 `1`인 비트를 하나씩 세지만, `Integer.bitCount()`는 같은 작업을 Java 표준 메서드로 처리한다.
- Java의 `int`는 32비트로 크기가 고정되어 있으므로 시간 복잡도는 `O(1)`, 보조 공간 복잡도도 `O(1)`이다.
- 정수의 비트 수가 입력에 따라 증가하는 일반적인 모델에서는 시간 복잡도를 `O(log n)`으로 볼 수 있다.

### Code (Python)

---

```python
def solution(n):
    usage = 0

    while n != 0:
        # 2로 나누어 떨어지면 건전지 소모가 없음
        if n % 2 == 0:
            n /= 2
        # 2로 나누어 떨어지지 않으면 한 칸 이동해야 함
        else:
            n -= 1
            usage += 1
    return usage
```

- Java 코드와 마찬가지로 목적지에서 역으로 이동하며 짝수이면 `2`로 나누고 홀수이면 `1`을 빼면서 사용량을 센다.
- `/=`는 Python에서 실수 나눗셈이므로 첫 나눗셈 이후 `n`은 `float`가 되지만, 문제 범위의 정수는 이 과정에서 정확히 표현되어 결과에는 영향을 주지 않는다.
- 최초 목적지 값을 `n`이라 할 때 시간 복잡도는 `O(log n)`, 보조 공간 복잡도는 `O(1)`이다.
